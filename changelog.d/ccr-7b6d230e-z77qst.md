### Added

- **Hermes Agent** (`forge init --tools hermes`, alias `hermes-agent`) is an emit target. Hermes reads the shared root `AGENTS.md` itself, so no instruction file is written; `forge sync` warns while a `.hermes.md`, `HERMES.md` or root `AGENTS.override.md` would hide it, since Hermes loads only the first project context file it finds. Hermes keeps MCP servers in its profile's `config.yaml` and reads no project MCP file, so the sync row prints the one `hermes mcp add forge-cortex --command forge --args cortex-mcp` command instead of writing a file, and `forge harness drift` lists the same step as manual. A `.hermes/` folder, `.hermes.md` or `HERMES.md` marks a repository as using Hermes.
- **Pi**, the pi coding agent (`forge init --tools pi`, aliases `pi-agent`, `pi-coding-agent`), is an emit target. Pi reads the shared root `AGENTS.md` itself (and loads only one context file per directory, so the generated `CLAUDE.md` never loads beside it); `forge sync` warns while a root `AGENTS.override.md` hides it. The managed MCP servers are written to `.pi/mcp.json` under `mcpServers`, which Pi loads after the person grants project trust; remote servers get a `${VAR}` bearer header. A `.pi/` folder marks a repository as using Pi.
- `forge init --tools all` now covers both, and the `--tools` help lists `opencode`, `hermes` and `pi`.
