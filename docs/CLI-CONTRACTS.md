# Command contracts

What a script can rely on when it calls a ForgeKit command. This page covers the commands
that have left the Labs group; a Labs command can still change its output in a minor release.

## The production bar

A command leaves Labs, and its group in `forge --help` changes, when it meets all of these:

1. **Complete help.** `forge <command> --help` lists every flag the command reads, the forms
   each flag applies to, and its exit statuses. A test reads each handler's source and fails
   when it reads a flag its help does not declare (`test/contracts.test.js`).
2. **Strict arguments.** A flag that is not in the help is refused before the command runs,
   with the nearest correct flag suggested: `forge deja "retry" --jsn` exits 1 with
   `unknown flag --jsn (did you mean --json?)`. So are a flag given to the wrong form
   (`uicheck contrast … --mint`), a value outside its range (`rank --top 0`) and a flag that
   only makes sense with another (`imagine … --sandbox off` without `--run`). Parsing is
   Node's built-in `util.parseArgs`, driven by the same flag list that `--help` prints
   ([`src/cli/args.js`](../src/cli/args.js)).
3. **A versioned JSON contract.** `--json` prints exactly one JSON document on stdout. Its
   shape is declared in [`src/contracts.js`](../src/contracts.js), and CI runs every form
   below in a fixture repository and checks the output against it.
4. **One exit status.** The exit status is the same with and without `--json`. Every exit
   status is listed in the command's help and in the table below.
5. **Failure cases tested.** Missing arguments, refused input and absent prerequisites
   (no code atlas, a dirty tree, a missing file) are tested, and on a usage error stdout
   stays empty so a script never parses half a result.

## What a contract promises

- The fields listed below are present with the stated types. A field marked `?` may be
  `null` or absent.
- A new field may appear in any release. Read the fields you need and ignore the rest.
- Removing or renaming a listed field, or changing its type, is a breaking change: it ships
  only in a new major version, with the contract's version raised.
- Text output, the form without `--json`, is for people and can change in any release.

## Exit statuses

ForgeKit uses two exit statuses. `0` means the command did what was asked, including
advice that found something, such as drift or a collision. `1` means a check failed, input
was refused, a prerequisite was missing, or the command line was wrong. On `1`, the reason
is on stderr. Commands whose JSON also carries a refusal say so in the table.

## Limits

- Contracts describe structure, not correctness. `imagine` predicts from a code graph built
  with regular expressions, so its targets and predicted breaks are estimates; a task that
  names no symbol or file has no targets. `lean`, `anchor`, `diagnose` and `collide` give
  advice and never fail on what they find.
- `uicheck visual` and `uicheck interact` need a browser runtime (`playwright-core`). Without
  one they exit 0 and report `skipped`, so their JSON is not covered by a contract yet.
- The guard checks the shape of a command line, not the meaning of free text. A task or
  goal that itself starts with `--` is read as a flag.
- `dash --json` promises only its start line. The dashboard's HTTP routes (`/api/data`,
  `/api/harness` and the rest) are the page's own interface and can change in any release.
- The report's HTML layout is for people; read the ledger itself (`forge ledger`) for data.
