---
title: "Advisor pairing"
description: "Configure Claude Code's advisor tool once, emit it into Claude Code's settings and AGENTS.md, and check the main/advisor pairing before Claude Code refuses it."
---

Claude Code's [advisor tool](https://code.claude.com/docs/en/advisor) lets the main model consult a
second, typically stronger model at key moments of a task: before committing to an approach, when
an error keeps recurring, and before declaring the task done. The advisor receives the whole
conversation and returns guidance the main model applies. It runs server-side on the Anthropic
API, is billed at the advisor model's rates per call, and is on only when the `advisorModel`
settings key names a model Claude Code accepts for the session's main model.

`forge advisor` makes that choice part of the repo's config, emits it, and checks the pairing
first, so a configured advisor that Claude Code would silently drop is caught before the session.

## Set it

```bash
forge advisor set opus              # this repo
forge advisor set fable --global    # every repo on this machine
forge advisor                       # advisor, main model, pairing verdict, rules
forge advisor off                   # remove it again
```

Per repo, the choice lives in `.forge/forge.config.json` and `forge sync` (run by `set`) emits
two things:

- `advisorModel` in the repo's `.claude/settings.json`, every other key preserved, removed again
  on `off`. This is the one key Forge owns in that file.
- An **Advisor** section in `AGENTS.md`, so every tool that reads it knows when to consult the
  advisor and when not to.

With `--global`, the choice lives in the user-level `forge.config.json` and Forge writes
`advisorModel` into `~/.claude/settings.json` directly, the same file Claude Code's own
`/advisor` command saves to, with the same "GLOBAL — affects all repos" line `forge init` prints.
Repos pick up the Advisor section on their next sync. The repo's choice wins over the global one.

<Note>
  A pick made with `/advisor` inside Claude Code is personal: `forge advisor` reports it and
  checks its pairing, but never emits it into the shared `AGENTS.md`. Run `forge advisor set`
  to make it the repo's.
</Note>

## The rules

| Id | Default | What it asks |
| --- | --- | --- |
| `advisor.before-approach` | on | Consult the advisor before committing to an approach on a multi-step task. |
| `advisor.recurring-error` | on | The same error after two attempts: stop and consult before trying again. |
| `advisor.before-done` | on | Before declaring done, an independent check of the result against the request. |
| `advisor.risk` | on | Consult before changing money, auth, secrets, migration or security code. |
| `advisor.evidence-wins` | on | Guidance that contradicts the files or a failed step: surface the conflict, never follow blindly. |
| `advisor.not-for-trivia` | on | No consultation on short, well-specified tasks: every call re-reads the whole conversation at the advisor's rate. |

```bash
forge advisor rule off advisor.before-done   # this repo; add --global for every repo
forge sync
```

## Check a pairing

Claude Code ranks models by capability for the advisor role; an advisor must rank at or above
the main model. Haiku can call the advisor but never act as one; Sonnet 4.5, Opus 4.5 and older
main models do not support it; a Fable main model takes only a Fable advisor.

```bash
forge advisor check sonnet opus              # ok
forge advisor check claude-opus-5-5 sonnet   # refused, exit 1
forge advisor pairings                       # the whole table
forge advisor pairings claude-opus-4-8       # one main model: accepted advisors and the suggested one
```

| Main model | Accepted advisors |
| --- | --- |
| Haiku 4.5 | Fable, Opus, Sonnet |
| Sonnet 4.6 | Fable, Opus, Sonnet |
| Opus 4.6 | Fable, Opus, Sonnet 5 or later |
| Sonnet 5 | Fable, Opus 4.7 or later, Sonnet 5 or later |
| Opus 4.7 or 4.8 | Fable, Opus 4.7 or later, Sonnet 5.5 |
| Sonnet 5.5 | Fable, Opus 5 or later, Sonnet 5.5 |
| Opus 5 or 5.5 | Fable, Opus 5 or later |
| Fable 5 | Fable 5.1 or Fable 5 |
| Fable 5.1 | Fable 5.1 |

The table ships as data in `source/advisor.json` with the date it was verified against the Claude
Code docs. An alias (`sonnet`, `opus`, `fable`) stands for the family's newest row. A model newer
than the table is accepted with a note and reported as **unverified**, since Claude Code validates
the pairing at launch. `set` refuses Haiku and pre-advisor models outright; a pairing the current
main model would refuse is saved with a warning, as Claude Code itself does, and activates once
the main model allows it.

The main model the check runs against is `ANTHROPIC_MODEL`, else Claude Code's settings
(`.claude/settings.local.json` > `.claude/settings.json` > `~/.claude/settings.json`), else the
account default, in which case the verdict is unverified.

## Where else it shows up

- The prompt-time substrate advisory adds one line when an advisor is configured and the prompt
  is a decision point: under-specified, routed to a premium tier, or touching money, auth,
  secrets, migrations or security.
- The doom-loop advisory names the advisor when the same failure recurs; that is the moment the
  docs say to consult it.
- `forge doctor` has an `advisor` row: the pairing verdict, and a warning when
  `CLAUDE_CODE_DISABLE_ADVISOR_TOOL=1` or a variable that turns Claude Code's feature-flag
  fetching off (`DISABLE_TELEMETRY`, `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`) keeps the
  advisor off whatever is configured.

<Warning>
  The rules are instructions, not hooks: Claude decides when to call the advisor, and there is no
  setting that caps or forces a call. The advisor is Anthropic-API only (not Bedrock, Google Cloud
  or Microsoft Foundry) and experimental; the pairing table can change with Claude Code releases,
  so `forge advisor check` is a pre-flight, and Claude Code's own validation is the authority.
</Warning>
